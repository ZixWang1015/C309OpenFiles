1. 使用GPT-Luna或其他部署于国外的模型时，需要在中断先设置proxy，这样比较简洁：
```
export HTTP_PROXY=http://127.0.0.1:22222
export HTTPS_PROXY=http://127.0.0.1:22222
export NO_PROXY=localhost,127.0.0.1 
```

2. 混元/小米等厂商提供的性价比模型完全不支持严谨的科学发现，他们在编码时为了快速解决bug总是会钻空子，导致最后代码层级实际上是一团糟，我建议：只有当你对项目细节有90%以上把控能力时，才可以直接使用

3. 为了避免模型跟着错误的ToDo list一直做一直错，一定要让他根据ToDo list一步一步做，并且每一步插入人工审核或GPT/Claude审核，避免最后浪费大量时间

4. 为了避免浪费时间得到错误的结果，还要花时间去debug，我建议使用以下的工作流：先将整体需求交由GPT Chat做分析并输出带有详细接口的markdown文档，再由Codex根据项目细节进行特定的适配，再由简单模型进行相关代码的编写和运行，最后再由Codex根据特定脚本/产物进行验收并生成审核用markdown文件，最后的最后使用markdown文件与GPT Chat详细讨论并验收这一部分工作
